# Conventions

- **Library-first design.** This module is consumed by other Go programs via `go get github.com/servercurio/go-library-starter@<version>`. There is no application lifecycle, no Cobra command tree, no `Application` type, no signal handling. Don't introduce them.
- **No Viper.** Configuration goes through `pkg/config` (YAML/JSON file loader) and `pkg/env` (typed env-var hydration). Layered precedence is **defaults → file → env**; a flag layer is the *consumer's* responsibility and lives in their CLI, not here. Don't pull Viper in.
- **Public packages live under `pkg/`.** Add new packages as `pkg/<name>/{package.go, <impl>.go, <impl>_test.go, example_test.go}` and mirror the shape of `pkg/greeter`. Don't hide reusable code under `internal/` — consumers can't import that.
- **Options-struct constructors.** Every public type that takes more than one configuration argument is built via `New(opts Options)` where `Options` is a value-typed struct whose zero value is valid. Fall back to documented defaults inside `New`; do not validate at the call site.
- **Godoc Examples on every exported function.** Add at least one runnable `Example*` function to a package's `example_test.go` (with a `_test` package suffix). The `// Output:` block doubles as a unit test and as the godoc snippet.
- **Table-driven tests.** Use `t.Run` per case and the `stretchr/testify` `assert` / `require` helpers already in `go.sum`. Library code does not call `panic` for control flow.
- **No global state except loggers.** `logging.Default` is the one tolerated package-level global because it is the actively-managed sink. Everything else is constructed and passed via dependency injection.
- **Errors are categorized via `joomcode/errorx` namespaces** (see `pkg/errors/fs.go`, `pkg/errors/pool.go`, and the per-package `<Pkg>Errors` namespace shown in `pkg/greeter`). Don't introduce ad-hoc `errors.New` / `fmt.Errorf` for new error categories.
- **Goroutine pool is shared via `pool.New(...)`.** The starter doesn't construct a package-level singleton — the consumer creates a `*Pool` and threads it where needed. If you write code that needs a worker pool, accept a `*pool.Pool` as a constructor argument; don't reach for `ants` directly.
- **Sign every commit, in two ways.** Contributor commits must be (1) GPG-signed — set `git config commit.gpgsign true` (and `user.signingkey <KEY-ID>`) so `%G?` shows `G` on `git log --show-signature` — and (2) carry a DCO `Signed-off-by:` trailer, which the per-clone `prepare-commit-msg` hook documented in `.claude/git-hooks.md` auto-appends. Both apply to merge / squash subjects too. The release flow's automated `chore(release)` commits already meet both requirements (see `.github/workflows/800-call-semantic-release.yaml`); contributor commits must match. Don't bypass either with `--no-gpg-sign` or `--no-verify`.
- **Supply-chain signing: hashes / manifests, not artefacts.** This starter releases only a signed git tag + signed source SBOM. The SBOM is itself a manifest (CycloneDX), so it is signed directly (`sbom.json.asc`, `sbom.xml.asc`); there are no binaries to hash. If a future addition does ship binaries, sign the hash file (`<binary>.sha256.asc`), not the binary.
